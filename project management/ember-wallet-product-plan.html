ADR-001 · One decision owner per signing use case

Status: Accepted 16 September 2026. During the first live SDK conformance attempt, the SDK runner created a cover lifecycle while Ember independently treated the resulting Wallet Standard requests as a second product signing flow. That produced contradictory account and request states: active cover could appear at the wallet level while the ownership challenge or setup payment correctly remained uncovered. The run was stopped before either transaction was signed or broadcast.

Decision: an SDK conformance run uses a dedicated neutral external Wallet Standard QA signer and the SDK runner owns that run's session, cover decision, approvals, broadcast and report. Ember is explicitly rejected as that signer. In the Chrome product, Ember owns the complete session, cover decision, approval, vault signing, broadcast and evidence flow. Android will follow the same product-owned boundary through its native protected-signer adapter.

Rejected design: no privileged conformance bypass, trusted-dapp flag or externally injected decision is permitted. A dapp-controlled path around Ember's decision would invalidate the product's protection premise and create two authorities for the same approval.

Product signing policy: the SDK's result describes cover; it does not decide whether the wallet may sign. A fresh covered decision is the only state presented as protected and it produces post-sign evidence. If cover is genuinely not offered (not_covered or unsupported), the user may explicitly acknowledge the risk and sign without cover. If the service is unavailable, the wallet offers retry and may continue only with the same explicit uncovered acknowledgement. An expired covered decision must be rechecked. Ownership messages and the one-time cover-purchase payment are explicit setup flows and must never imply that the setup action itself is covered.
